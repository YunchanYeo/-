# 위챗페이 실결제 테스트·연결 메모

이 문서는 **모의(mock)가 아닌 실제 JSAPI 결제**를 검증하기 위해 진행·확인한 사항과, **폰에서 서버 접속**·**알리클라우드에서 며칠 뒤 끊김**에 대한 기술적 설명을 정리합니다.

## 관련 코드·설정

- 백엔드: `WECHAT_PAY_MOCK=false` 이고 위챗페이 V3 환경변수가 모두 채워지면 `orderService`에서 실统一下单 → 프론트는 `wx.requestPayment` (`frontend/pages/order/order-confirm/pay.js`).
- 환경변수 예시: `backend/.env.example`
- 商户证书·私钥: `backend/certs/wechat-pay/README.md`
- 결제 콜백: `POST /api/wechat-pay/notify` (공인 **HTTPS** 필수)

---

## 1. 진행·확인 사항 요약

### 1.1 Mock 끄기

- `WECHAT_PAY_MOCK` 기본은 mock 모드입니다. **문자열 `false`** 로 두어야 실결제 경로로 갑니다 (`process.env.WECHAT_PAY_MOCK !== 'false'` 조건).

### 1.2 실결제에 필요한 환경변수

다음이 비어 있지 않아야 `loadWechatPayConfigFromEnv()` 가 설정을 반환하고 실 JSAPI 를 호출합니다.

| 변수 | 역할 |
|------|------|
| `WECHAT_APPID` | 미니프로그램 AppID (반드시 **小程序** AppID) |
| `WECHAT_MCH_ID` | 微信支付商户号 |
| `WECHAT_PAY_SERIAL_NO` | 商户 API 证书序列号 |
| `WECHAT_PAY_PRIVATE_KEY` 등 | 商户 API 私钥 |
| `WECHAT_PAY_NOTIFY_URL` | 비동기 알림 URL (공인 HTTPS) |
| `WECHAT_PAY_API_V3_KEY` | API v3 키 (정확히 **32바이트**) |

운영에서는 알림 서명 검증을 위해 **`WECHAT_PAY_PLATFORM_CERT_PEM`**(또는 파일 경로) 설정을 권장합니다.

### 1.3 프로브 스크립트

```bash
cd backend && npm run probe:wechat-pay
```

- 商户 **私钥·证书序列号·商户号** 조합이 위챗과 맞는지 빠르게 확인하는 용도입니다.
- `GET /v3/certificates` 가 商户 플랫폼 설정 때문에 막힐 수 있어, 스크립트는 **JSAPI 试探请求** 로 대체할 수 있습니다.
- **`WECHAT_PAY_API_V3_KEY` 가 올바른지는 이 스크립트만으로는 완전 검증되지 않습니다.** 실제 **支付结果通知** 수신·복호화로 확인하는 것이 확실합니다.

### 1.4 소액(「진짜 돈」) 테스트

- 주문 **`totalAmount` 단위는「分」** 입니다. **0.01 위안 = `1`** (1分).
- `totalAmount > 0` 일 때만 실위챗统一下单 경로를 탑니다.

### 1.5 로그인·openid

- 실결제 시 DB 사용자의 **위챗 `openid`** 가 필요합니다.
- **`dev_` 로 시작하는 개발용 openid** 는 백엔드에서 실결제를 거절합니다. **실기 또는 체험판**에서 위챗 로그인으로 받은 openid 를 사용해야 합니다.

### 1.6 `APPID_MCHID_NOT_MATCH` (프로브 또는 실下单 시)

위챗 오류 예:

```json
{"code":"APPID_MCHID_NOT_MATCH","message":"appid和mch_id不匹配，请检查后再试"}
```

**의미:** `.env` 의 **`WECHAT_APPID`** 와 **`WECHAT_MCH_ID`** 가 위챗페이에 **绑定(연동)** 되어 있지 않습니다.

**조치:**

1. [微信支付商户平台](https://pay.weixin.qq.com/) 에 해당 商户로 로그인.
2. **产品中心 → AppID账号管理** 에서 **현재 미니프로그램 AppID** 를 이 商户에 추가·授权.
3. **微信公众平台(小程序)** 쪽에서 商户 연동 요청이 있으면 **승인**.

또는 **이미 해당 미니프로그램과 연동된 다른 商户号**가 있다면, `.env` 의 **商户号·그 商户용 API 证书·私钥** 를 그쪽으로 통일합니다.

### 1.7 끝까지 검증 체크리스트

1. 미니프로그램에서 소액 주문 → `wx.requestPayment` 성공.
2. **微信支付商户平台** 에서 거래 내역 확인.
3. 서버 로그에서 **`POST /api/wechat-pay/notify`** 수신 및 주문/DB 상태 반영 확인.

## 2. 폰에서 서버 연결이 되는 이유 — 「한국 서버」 때문인가?

**아니요. 서버가 한국에 있다고 해서 특별히 폰과 잘 붙는 것은 아닙니다.**

- 스마트폰은 **Wi-Fi 또는 이동통신**으로 인터넷에 나가고, **공인 IP·도메인·HTTPS** 로 열려 있는 API 라면 **지역과 무관하게** 접속할 수 있습니다 (방화벽·정책 제한이 없다는 전제).
- 중요한 것은 **「서버가 한국」이 아니라** 다음입니다.

| 항목 | 설명 |
|------|------|
| **공인 접근** | ECS/클라우드에 **탄력 공인 IP(EIP)** 또는 고정 도메인이 있고, **보안 그룹**에서 443(또는 사용 포트)이 허용되는지 |
| **HTTPS·인증서** | 미니프로그램·위챗은 **유효한 TLS** 를 요구하는 경우가 많음 |
| **미니프로그램 서버域名** | `wx.request` 대상 도메인이 **微信公众平台 → 开发 → 开发管理 → 服务器域名** 에 등록·검증되어 있어야 함 |
| **프론트 `apiBaseUrl`** | 실제로 호출하는 주소가 위에 등록한 도메인과 일치하는지 |
| **백엔드 기동** | 프로세스가 살아 있고, 리버스 프록시(Nginx 등) 설정이 맞는지 |

즉, **한국 리전이어도 되고 중국 리전이어도 됩니다.** 다만 **중국 사용자 대상 서비스**면 지연·ICP·위챗 정책 때문에 **국내 또는 홍콩 등 가까운 리전**을 쓰는 경우가 많을 뿐입니다.

## 3. 알리클라우드에서 며칠 뒤 갑자기 안 될 때 (점검 순서)

「며칠 전까지 되다가 갑자기 API 가 안 됨」은 **서버 위치**보다 아래 원인이 흔합니다.

1. **과금·试用 만료**  
   - ECS/경량앱 서버 **试用期满** 또는 계정 **欠费** 시 인스턴스 정지·네트워크 차단.

2. **공인 IP 변경**  
   - 인스턴스를 **재생성·재시작**하면서 **EIP 를 해제**했거나, **고정 IP 없이** 배포했다가 IP가 바뀜 → DNS는 옛 IP 를 가리킴.

3. **보안 그룹·방화벽**  
   - 규칙이 바뀌었거나, 실수로 443/백엔드 포트가 막힘.

4. **SSL 인증서 만료**  
   - Let’s Encrypt 등 **90일 주기**; 자동 갱신 실패 시 HTTPS 거부 → 미니프로그램 요청 실패.

5. **프로세스 종료**  
   - `pm2`/systemd/docker 가 재부팅 후 안 올라감, OOM 으로 크래시.

6. **위챗 쪽 설정**  
   - 서버域名 검증 만료·변경, **request 合法域名** 과 실제 API 도메인 불일치.

7. **OSS·별도 키(미디어 등)**  
   - API 자체와 무관할 수 있으나, 이미지·업로드만 깨지는 증상과 구분.

**권장:** 장애 시 `curl -v https://你的API域名/api/health` 로 **TLS·응답**을 먼저 확인하고, 클라우드 콘솔에서 **인스턴스 상태·EIP·보안 그룹·과금**을 같이 봅니다.
